# Компактный iPhone: AX5 visual review CI7

Основной раздел ниже сохраняет состояние и findings **на момент CI7**. Дополнения CI9 для [iPad18](#дополнение-ci9-ipad18-после-ui-исправлений) и [iPhone SE](#дополнение-ci9-iphone-se-проверка-компактных-исправлений) проверяют более поздний production source. Именно supplement iPhone SE содержит повторное visual evidence двух исходных P2.

Проверено 2026-11-06 по [CI7 42252310226](https://github.com/janickiy/meetspace_ios_mobile/actions/runs/42252310226), source **`c88fe5adebe7395b4f43ab51b6c6369aa95d09f5`**. Устройство — iPhone SE (3rd generation), simulator **iOS 18.6**, Xcode 26.3 (17C529), scope `audit`; [environment](evidence/accessibility-attempt07/iPhone18-environment.json). Кадры — **750×1334 pixels, 375×667 pt**. Наблюдения ниже относятся к portrait AX5 (`UICTContentSizeCategoryAccessibilityXXXL`), если явно не указано иное.

Итог задания iPhone18: **13 PASS / 2 FAIL из 15**, а не общий PASS. `testAccessibilityStage08LargeTextLiveFlow` и `testLargeTextNavigationAndAppearance` прошли; `testAccessibilityStage08CoreScreens` остановился в profile navigation, account-deletion test также завершился ошибкой. См. [summary](evidence/accessibility-attempt07/iPhone18-summary.json) и [точные строки лога](evidence/accessibility-attempt07/iPhone18-review-test-results.txt).

**Это не native verification более позднего `6b6d1bb` или последующих UI-исправлений.** Исправление направления поиска профильной ссылки уже подготовлено после tested source; новый PageHeader fix описан ниже как pending. Геометрия на сохранённых PNG принадлежит `c88fe5a`. Полный текущий audit и проверка новых исправлений остаются PENDING.

## Доказательства и границы

Просмотрены все 15 AX5 PNG live flow, один dark/demo PNG и один normal-size profile visible-retest PNG. **17 изображений скопированы без изменения байтов**, без crop/resize/ретуши. [Review manifest](evidence/accessibility-attempt07/iPhone18-review-manifest.json) содержит SHA-256, исходные filenames, timestamp и testIdentifier; [оригинальный export manifest](evidence/accessibility-attempt07/iPhone18-export-manifest.json) сохранён отдельно. Pixel coordinates ниже приблизительно оценены по полным изображениям; это не выдаётся за AX frames или отдельные измерения hit areas.

PASS сценария означает, что проверенные переходы и assertions выполнены. Он не обнаруживает автоматически каждое визуальное многоточие, неудобный перенос или скрытый участок контента: ниже есть **реальные visual findings несмотря на PASS**. Проверка VoiceOver на физическом устройстве не выполнялась.

## Нижняя навигация и demo

Во всех workspace AX5 PNG присутствуют **и иконки, и слова** «Встречи», «Чаты», «Профиль». Боковые labels переносятся на две строки, а иконки стоят рядом; ни один label не скрыт и не обрезан многоточием. Видимая панель занимает приблизительно y1164…1334 px, то есть около **85 pt** из 667 pt высоты экрана. Это оценка изображения, не точная frame-метрика XCTest.

Фактические пройденные assertions строже простого визуального впечатления:

- Live AX5 flow: `tab.profile.frame.height < app.frame.height / 5`, то есть <133.4 pt на данном устройстве.
- Demo flow: сумма высот `tab.profile` и `exitDemo` меньше четверти экрана, то есть <166.75 pt. Прежний CI3 результат 175.5 pt больше этого предела был FAIL; новый CI7 сценарий прошёл.

[Demo dark appearance PNG](evidence/accessibility-attempt07/screenshots/iPhone18-appearance-dark-large-text.png) показывает выбранную тёмную тему, целые названия «Системная», «Светлая», «Тёмная» и доступную нижнюю навигацию. Ниже начинается раздел размера текста — его полное содержимое этим кадром не покрыто. Нижние labels сохранены; верхний demo indicator/exit используют уже существующий icon layout при AX. Этот review не добавляет скрытие текста или cap Dynamic Type.

## Core audit остался частичным

Сохранены три **накопительных**, а не независимых набора: [welcome progress](evidence/accessibility-attempt07/iPhone18-stage08-audit-progress-welcome.json) — 1 finding, [messages](evidence/accessibility-attempt07/iPhone18-stage08-audit-progress-messages.json) — 4, [profile](evidence/accessibility-attempt07/iPhone18-stage08-audit-progress-profile.json) — 6. Их нельзя суммировать как 11 разных замечаний.

В последнем progress `addAccount` первоначально находился в `(24,654,327,44)` pt, затем был целиком прокручен в видимую область; повторный contrast audit не сообщил target finding. [Normal-size visible-retest PNG](evidence/accessibility-attempt07/screenshots/iPhone18-stage08-accessibility-profile-visible-addAccount.png) подтверждает целую кнопку. После этой прокрутки raw frame «Календарь» стал `(41.5,-14,98.5,17)` и был помечен **outside retest viewport: no contrast measurement**, а не измеренным PASS.

Следующий переход к календарю использовал прежний однонаправленный `reveal`, продолжал прокрутку вниз и завершился assertion на строке37. Это фактическое подтверждение найденного ранее navigation bug; исправление на direction-aware `revealEntireText(link)` не входило в tested `c88fe5a`. Core audit не дошёл до calendar/recordings/folders/settings, итогового `stage08-accessibility-issues` attachment нет. Успешный **отдельный AX5 navigation flow** не заполняет этот пробел общего audit.

Итог именно CI7 — ограниченное подтверждение конкретных AX5 states, две visual findings и частичный автоматический аудит. Global accessibility/WCAG/device PASS не заявляется. Результат более позднего source рассматривается отдельно ниже.
