# Stage 8: независимая проверка accessibility, попытка 02

Проверено 2026-11-06: iPhone 17 Pro Max / iOS 26, CI [42233879641](https://github.com/janickiy/meetspace_ios_mobile/actions/runs/42233879641), исходники `acc193a47e9f94016ff2345f76f6294f53fcb13c`. Это разбор неуспешной попытки, **не заключение о прохождении accessibility-аудита**. Из 29 сырых замечаний 26 относятся к Dynamic Type, два — к контрасту, одно — к обрезанию текста. Независимый просмотр выявил ещё две реальные проблемы компоновки при AX5; рост шрифта сам по себе их не обнаруживает.

Просмотрены все 14 полных PNG: welcome, messages, profile, calendar, recordings, folders, settings при обычном размере и `UICTContentSizeCategoryAccessibilityXXXL` (AX5). Оригиналы скопированы без изменений; [manifest](evidence/accessibility-attempt02/manifest.json) содержит соответствие имён XCTest и SHA-256. Изображения 1320×2868 соответствуют 440×956 pt. [Сырые 29 замечаний](evidence/accessibility-attempt02/iPhone26-issues.json) сохранены отдельно от интерпретации.

## Подтверждённые проблемы компоновки

**После review исправления внесены в исходники; повторная CI/визуальная проверка пока PENDING.** В календаре и записях внешний native menu `Picker` заменён на `Menu` с явным `Text` label, допускающим несколько строк и intrinsic height (`fixedSize(horizontal: false, vertical: true)`, minimum hit height44). Внутренний `Picker` сохранён: те же bindings, варианты и selected semantics. Календарь переносит scope/time-zone controls в вертикальную компоновку, когда их полная ширина не помещается. Фильтры записей также выбирают вертикальную компоновку по полной ширине labels. Новые снимки должны подтвердить результат; PNG ниже сохраняют дефект исходного CI2 без ретуши.

Ни одна из двух проблем не указана непосредственно в raw 29: автоматический аудит и ручной просмотр дополняют друг друга.

Для точечных повторных проверок добавлены IDs: `calendar.scope`, `calendar.periodTitle`, `calendar.today`, `calendar.weekday.0`…`.6` (Monday0…Sunday6, одинаковый смысл для week strip и month header), `recordings.filterHint`, `recording.date.<lowercase UUID>`, `recording.status.<lowercase UUID>`, `recordings.retentionNotice`, `recordingStatusFilter`. Существующий `recordingModeFilter` сохранён на внешнем menu control. Общий VoiceOver label меню — назначение фильтра, value — текущий выбранный вариант.

## Измерение шрифта и пределы доказательства

[Оригинальный CI2 hosting receipt](evidence/accessibility-attempt02/iPhone26-actual-font-scaling.json) содержит 14 samples: размеры 10, 11, 12, 14, 20, 28, 34 для двух начертаний `.body`. Это реальный `UIHostingController.sizeThatFits`, не расчёт через коэффициент и не mock. Высоты одной строки:

| Base size | Обычный `.large` | AX1 | AX5 |
| --- | ---: | ---: | ---: |
| 10 | 12.33 | 20.67 | 39.00 |
| 11 | 13.33 | 20.67 | 37.67 |
| 12 | 14.67 | 23.00 | 41.33 |
| 14 | 17.00 | 26.67 | 47.33 |
| 20 | 24.33 | 35.33 | 57.00 |
| 28 | 34.00 | 46.00 | 68.00 |
| 34 | 41.33 | 52.33 | 70.33 |

Оба начертания дали одинаковые перечисленные line heights. Все 12 категорий есть в receipt. Расширение `TypographyAccessibilityTests` на все 24 base sizes и отдельные semantic styles `.caption/.title2/.title/.largeTitle` с проверкой строго возрастающих AX1→AX5 уже подготовлено root, но его будущий результат нельзя подменять CI2 receipt.

Два реальных menu P2 на снимках показывают, почему одного успешного font-hosting теста недостаточно. Также верхний viewport не покрывает все строки длинного экрана, и `.isHittable` не гарантирует полную видимость текста. Для повторной проверки нужны целые bounds над tabbar, отсутствие пересечений соседних controls и визуальная полнота выбранных labels при AX5. На нормальных и AX5 снимках profile/settings дополнительных пересечений не обнаружено; длинные слова переносятся, содержимое ниже viewport доступно прокруткой. Это ограниченное visual review, а не полная проверка VoiceOver на устройстве.

Apple описывает разбор каждого результата отдельно, узкий handler по element/type и отказ от подавления остальных ошибок; автоматический аудит не заменяет проверку с реальными assistive technologies: [WWDC23, Perform accessibility audits for your app, 9:34 и 11:41](https://developer.apple.com/videos/play/wwdc2023/10035/). Для масштабируемого custom-font API см. [Font.custom(_:size:relativeTo:)](https://developer.apple.com/documentation/swiftui/font/custom(_:size:relativeto:)). В этом отчёте не предлагается отключать `.dynamicType`, `.contrast` или `.textClipped` целиком.
