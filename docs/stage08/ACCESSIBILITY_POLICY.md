## Raw findings и условие отказа

Семь экранов — welcome, messages, profile, calendar, recordings, folders, settings — проверяются по категориям contrast, element detection, hit region, sufficient element description, trait, Dynamic Type и text clipping. Категории запускаются отдельно; contrast — до временных изменений размера текста аудитом.

Общий сборщик `collect` используется и для первоначального прохода, и для contrast retest. В callback он один раз вызывает публичный `try? issue.element?.snapshot()`, затем копирует `auditType`, `compactDescription`, `detailedDescription` и атрибуты immutable snapshot (`identifier`, `label`, `frame`) в value-only `AuditFinding`. Это **один snapshot вместо трёх отдельных live-чтений element attributes** в промежуточной реализации. Исходный issue и связанный с ним `XCUIElement` не сохраняются и не читаются после callback; внутри callback нет обхода app hierarchy, вычисления viewport или review predicates.

После возврата `performAccessibilityAudit` сборщик отдаёт frozen findings; тест ждёт 0.5 s и только затем выполняет review/viewport-проверки, используя сохранённые поля и текущие app queries **вне callback**. Такая пауза даёт время на восстановление временных trait changes, но сама по себе не доказывает стабильность любого layout. Сравнение frozen issue frame с позднее полученной геометрией контейнеров остаётся границей метода; результаты нового native CI требуются отдельно.

Если snapshot отсутствует или выбрасывает ошибку, ID/label сохраняются пустыми, frame отсутствует, но type/summary/detail сохраняются. Такой finding не соответствует текущим exact cases и остаётся `unresolved`, а не получает автоматическое исключение. Если audit выбрасывает ошибку вне узкого условия повторной попытки ниже, уже собранные findings записываются как `unresolved`, создаётся `stage08-accessibility-issues`, затем ошибка пробрасывается и тест падает. Любой полученный callback запрещает engine retry даже при недоступном snapshot.

Callback возвращает `true`, чтобы собрать findings вместо остановки на первом; **это не итоговый PASS**. Каждому сохраняется решение. Финальный assert требует отсутствия `unresolved` и незавершённых `deferred:`. Неизвестный finding первоначального прохода остаётся FAIL, кроме явно описанного отложения contrast вне viewport. При повторном проходе неизвестный **видимый** finding также остаётся FAIL; для других элементов вне retest viewport есть отдельная категория «не измерено», описанная ниже. Неуспешный engine pass сам по себе не считается PASS; восстановление учитывается только после завершённой повторной проверки по правилу ниже. Existence/visibility assertions и ошибки выполнения жестов этим правилом не охватываются.

JSON сохраняет `screen`, числовой `type`, `summary`, `detail`, `element`, `label`, `frame` и `resolution`. Полученные поля не удаляются при reviewed exception или повторном измерении; недоступные при snapshot поля остаются пустыми. После каждого экрана создаётся накопительный `stage08-audit-progress-<screen>`, в конце — `stage08-accessibility-issues`; при пойманной ошибке audit последний файл сохраняется также из `catch`. PNG фиксируют начальное состояние, каждый visible retest и AX5-состояния. При другом раннем падении итоговый JSON всё ещё может отсутствовать; progress/failure artifacts сохраняются как доступное свидетельство, а не трактуются как отсутствие проблем.

## Один ограниченный повтор engine timeout

В `04f70a3` `collect` даёт каждому pass свой `passID` и максимум две попытки. Повтор разрешён **только одновременно** при первой попытке, категории `.elementDetection` либо `.dynamicType`, exact `NSError.domain == "com.apple.xcode.xctest.accessibilityAudit"`, `code == -56`, `callbackCount == 0` и `findings.isEmpty`. Счётчик callbacks увеличивается первым действием closure, до snapshot. Основание allowlist — CI10 iPhone26 и CI13 iPad18; это не правило для остальных пяти категорий или произвольных ошибок.

Перед повтором первая ошибка записывается и прикрепляется в `stage08-audit-attempts`; затем тест ждёт 2 s и повторяет **тот же screen/category pass**. Код не выполняет навигацию/прокрутку и не снимает найденные accessibility issues. Состояние приложения может продолжать меняться само, в частности из-за audit trait overrides; пауза не гарантирует его неизменность. Второй error всегда пробрасывается; любой другой первый error либо первый error после callback также немедленно пробрасывается. Findings успешной повторной попытки поступают в тот же обычный handler и могут провалить тест. Тест не получает PASS только потому, что engine timeout принадлежит allowlist.

Cumulative receipts имеют `schemaVersion = 1`, `passID`, `screen`, `categoryName`, `categoryRawValue`, `phase` (`initial` / `visibleRetest`), номер `attempt`, `startedAtUTC`, monotonic `elapsedSeconds`, `callbackCount`, `findingsCount`, `outcome` (`completed` / `engineError`), `retryDecision` и `settleSecondsBeforeAttempt`. Для ошибки сохраняются `domain`, `code`, `description`; произвольный `userInfo` не сериализуется. Attachment создаётся при каждой ошибке до retry/throw и после завершённого экрана, поэтому первый timeout остаётся виден даже после восстановления. Если последующее немедленное assertion прекращает тест до конца экрана, самый поздний успешный receipt может остаться только в памяти; предыдущий error receipt уже прикреплён.

При разборе CI нужно различать clean first-attempt completion, **recovered engine timeout** и окончательный FAIL. Успешная вторая попытка не удаляет первую ошибку и не превращает исторический CI10/13 в PASS. Recovery для `04f70a3` пока **PENDING**; ни нужная длительность settle, ни отсутствие оставшихся traits после failed Dynamic Type pass из наличия таймера не выводятся.

## Видимая область и точная прокрутка

`contentViewport(identifier:label:in:)` начинает с `app.frame`, ограничивает верх navigation bar, низ — верхней границей `tab.profile`, затем пересекает эту область с подходящими `ScrollView.frame`. Audit передаёт frozen ID/label; `revealEntireText` использует overload `contentViewport(for:in:)` для текущего target. Принадлежность scroll view определяется поиском descendant с тем же identifier; при пустом ID — с тем же непустым label. Это **поиск по identity/label, а не непосредственное чтение ancestor chain**. Для уникальных fixture IDs он соответствует нужному контейнеру; одинаковые labels в разных scroll views могут сделать область излишне узкой. Произвольные перекрывающие окна и сложные clip shapes таким прямоугольным расчётом не моделируются.

`revealEntireText` требует existence, вычисляет viewport заново перед каждым из максимум 16 жестов, выбирает горизонтальное движение при выходе за его X-границы, иначе вертикальное, и ограничивает длину движения доступной областью. Жест использует `.slow`, press 0.1 s и hold 0.3 s. Для раннего завершения требуется containment с запасом 1 pt по X / 4 pt по Y; финальный assert после лимита использует полную область без этого запаса. Высота target должна помещаться в viewport. `.isHittable` не заменяет эту проверку.

Такая проверка доказывает только прямоугольные bounds выбранного элемента. Она не доказывает полноту соседней даты, всей карточки, отсутствие наложения внутри текста или читаемость каждого glyph; для этого остаются PNG и visual review.

Возврат в custom tab сохраняет scroll offset. В [CI3 iPhone18 raw](evidence/accessibility-attempt03/iPhone18-issues.json) `addAccount` имеет frame `(24,654,327,44)` ниже видимого профиля; retest прокручивает к нему и может оставить `openCalendar` выше viewport. Прежний `openProfileFeature` вызывал однонаправленный `reveal` со `swipeUp`, который уходил бы ещё ниже. Текущий source вызывает direction-aware `revealEntireText(link)` и сохраняет проверку min44 pt перед tap. Наличие этого исправления не является подтверждением всего нового native audit flow.

## Contrast вне viewport: отложенное решение и retest

Первоначальный `.contrast` finding с **непустым identifier** вне `contentViewport` получает `deferred: outside scroll viewport; requires fully visible retest`, а его index/ID — очередь повторной проверки. Это относится и к footer, и к другому идентифицированному тексту. Неидентифицированный неизвестный finding не исключается этим правилом.

После основных категорий каждый deferred target находится по ID, целиком вводится в viewport, снимается PNG `stage08-accessibility-<screen>-visible-<identifier>` и снова запускается `.contrast`. Все новые raw findings сохраняются. Исходная запись получает одно из трёх различных решений:

- `verified: fully visible contrast retest produced no target finding` — audit не сообщил target повторно;
- `reviewed: fully visible retest produced a reviewed finding` — finding сохранился и принят **конкретным** `reviewedCase`, это не отсутствие ошибки в raw;
- `retest failed; see unresolved finding` — новый target finding не принят; сохранённая `unresolved` запись приводит к FAIL.

Другие видимые findings повторного прохода также проходят обычный handler; неизвестные остаются FAIL. Другие элементы **вне retest viewport** записываются как `outside retest viewport: no contrast measurement`. Они не образуют новую рекурсивную очередь и сами этим проходом не проваливают тест: это граница покрытия, **не подтверждение их контраста**. Ранее queued первоначальные findings всё равно получают собственный retest. Эти записи нужно сохранять и проверять при разборе artifacts, не включать в число успешно измеренных элементов.

Зафиксированные ограничения нельзя превращать в blanket допуск `.contrast`.

## Text clipping, декоративный avatar и partial Dynamic Type

`welcome.heading` допускает только `.textClipped` на screen `welcome` с точным label `Команда ближе.\nИдей больше.`. [Review iPhone](ACCESSIBILITY_REVIEW.md) и [review iPad](ACCESSIBILITY_IPAD_REVIEW.md) показывают целый заголовок в normal/AX5 состояниях. Это не разрешение другим headings/type/labels; после layout changes нужны новые screenshots.

Отдельный avatar case: screen `messages`, label `ТЕ`, 44×44 pt с допуском <1, `.contrast` либо `.dynamicType`; frame целиком внутри `conversation.22222222-2222-4222-8222-222222222222`, а её доступный label содержит «Тестовый собеседник». Avatar скрыт от accessibility и дублирует полное имя. При AX5 инициалы действительно могут заменяться многоточием; этот декоративный случай не доказывает отсутствие truncation у другого текста.

Остальные Dynamic Type exceptions требуют **одновременно** `.dynamicType` и точный `compactDescription == "Dynamic Type font sizes are partially unsupported"`, затем один из следующих matches:

- `messages`: `messages.connectionStatus`.
- `calendar`: `calendar.heading`, `calendar.periodTitle`, `calendar.today`, `calendar.scopeTitle`, `calendar.timeZoneTitle`, `calendar.weekday.0`…`.6`, `calendar.hour.0`…`.23`.
- `recordings`: `recordings.filterHint`, `recordings.modeTitle`, `recordings.statusTitle`, а также `recording.date.<UUID>` / `recording.status.<UUID>` только четырёх fixture UUID выше.
- `folders`: `folders.subtitle`.
- Menu fallback: exact label «Все встречи» внутри `calendar.scope`, «GMT» внутри `calendar.timeZone`, «Все форматы» внутри `recordingModeFilter`, «Все статусы» внутри `recordingStatusFilter`; соответствующая кнопка существует, её frame содержит весь issue frame. Это дополняет stable child IDs, когда Apple отдаёт node без дочернего ID.
- Tab label: «Чаты» внутри `tab.messages`, «Встречи» внутри `tab.meetings`, «Профиль» внутри `tab.profile`. Теперь требуется полное frame containment в **соответствующем** tab, а не только нижняя Y-граница экрана.

Наличие часа в allowlist не утверждает, что каждый из 24 часов просмотрен на PNG. Unknown ID/type/subtype не исключается этим правилом. Причина Apple partial-warning неизвестна; гипотеза про нативные плато не считается доказанной.

## Реальный hosted font test и предел его результата

Матрица содержит **74 комбинации × 12 категорий** (888 измерений на устройство): 24 базовых размера `.body` плюс 13 пар размер/style, для Regular и SemiBold. Дополнительные пары — caption 9/10/11, title2 19/20/23, title 24/25/27/28, largeTitle 32/34/46.

Это реальный `UIHostingController` с `Text`, `MSTheme.font`, заданной `DynamicTypeSize` и `sizeThatFits` при свободных 10 000×10 000. Assertions проверяют положительную высоту, неубывающий рост XS…AX5, строгое увеличение AX1→AX5, AX5 >1.5 стандартной `.large` и наличие зарегистрированных Inter Regular/SemiBold.

CI3 [42240106296](https://github.com/janickiy/meetspace_ios_mobile/actions/runs/42240106296), source `586bfe8`, действительно выполнил расширенный тест успешно на всех четырёх конфигурациях: [iPhone18 receipt](evidence/accessibility-attempt03/iPhone18-font-scaling.json), [iPhone26](evidence/accessibility-attempt03/iPhone26-font-scaling.json), [iPad18](evidence/accessibility-attempt03/iPad18-font-scaling.json), [iPad26](evidence/accessibility-attempt03/iPad26-font-scaling.json). При обновлении этого документа проверено, что каждый JSON содержит 74 ряда по 12 heights и удовлетворяет указанным численным условиям. Старый CI2 receipt с 14 рядами не используется вместо этих результатов.

Font test **не доказывает отсутствие clipping, overlap, ограничивающей высоты или плохой hit area каждого product view**. Плато на отдельных малых категориях не устанавливают причину Apple warning.

## AX5 layout и системный Passwords prompt

`testAccessibilityStage08LargeTextLiveFlow` запускает `UICTContentSizeCategoryAccessibilityXXXL`, проходит семь экранов и сохраняет PNG. Дополнительно целиком открывается fixture conversation в messages; календарь прокручивается к 9/12/18 часам, записи — к статусам всех четырёх fixtures и retention notice. Полноту дат/всей карточки/букв, соседние пересечения и подписи tabs проверяют по снимкам отдельно от bounds assertions. [Compact review](ACCESSIBILITY_COMPACT_REVIEW.md) сохраняет исходные CI7 findings и последующие 32 AX5 PNG CI9 на SE/iPad mini: полный Messages heading, достижимая conversation row, новая широкая recording-card компоновка и полный footer фактически просмотрены. Сохранившиеся неудобные переносы и области вне viewport перечислены отдельно. Layout этих экранов не менялся между `f1eda3a` и `0216c99`; lifecycle-изменение push/account deletion и новый AX handler этим visual evidence не проверяются.

Этот SHA также содержит ограниченное 10-секундное ожидание исчезновения chat panel и клавиатуры перед последующим camera tap в conference-сценарии. Это отдельная защита от координатного перехода интерфейса, не accessibility exception и не основание объявлять сценарий пройденным до нового native результата.

Login harness сохраняет production AutoFill. После основного 12-секундного ожидания повторно ищет актуальную AX decline-кнопку и допускает максимум два нажатия с повторным опросом: медленный синхронный OCR может завершиться после deadline. Затем наличие блокирующей кнопки и недоступность workspace по-прежнему проваливают тест.

OCR fallback работает по текущему screenshot: accurate/en-US, language correction off, confidence ≥0.8. Title — либо одна normalized observation `savepassword`, либо соседние `save` над `password`, с разницей minX <0.03 и вертикальным gap <0.05 (координаты Vision bottom-left). `notnow` должен быть ниже title; tap вычисляется из его текущего bbox. Снимок перед нажатием сохраняется. [iPad evidence](ACCESSIBILITY_IPAD_CONTRAST.md) подтверждает конкретный двухстрочный случай и позднее появление AX, но не результат нового harness на iOS. Русский prompt поддержан AX lookup; OCR fallback по-прежнему распознаёт указанные английские слова. Успех для других системных dialogs этим не заявляется.

## Интерпретация итогов

[WWDC23 — Perform accessibility audits for your app](https://developer.apple.com/videos/play/wwdc2023/10035/) допускает расследование конкретного false positive и узкий handler; это не разрешение отключить category целиком.

Даже успешный новый CI будет означать прохождение заданных сценариев с documented reviewed exceptions и отдельными «не измерено» областями. Он **не означает blanket accessibility PASS, WCAG conformance или полную проверку VoiceOver/assistive technologies**. Raw findings, reviewed cases и результаты реальных повторных измерений должны оставаться различимыми. Новые UI counts и точный tested SHA вносятся только после получения следующего CI evidence.
